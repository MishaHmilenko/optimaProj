# Практичне заняття 12. FileMan — консольний переглядач і редактор файлів

Консольний застосунок на Python: переглядає вміст директорій, відкриває файли й редагує їх.
Усе працює в межах одного процесу, без повторних запусків. Термінал — Linux або macOS.

```bash
python3 files.py                        # поточна директорія
python3 files.py demo/trip-planner      # демо-папка з архіву
python3 files.py README.md              # одразу відкрити файл
python3 -m pytest -v                    # тести (281)
```

Знімки екрана й анімація роботи лежать у `docs/screenshots/`. Їх отримано зі справжнього
запуску `files.py` у псевдотерміналі (PTY), без жодних моків.

## Граф станів

```
                    Enter / → (каталог)
                   ┌──────────────┐
                   ▼              │
   запуск ──► ┌─────────┐ ────────┘          Enter (файл)          ┌────────┐
              │ BROWSE  │ ─────────────────────────────────────► │  VIEW  │
              │ список  │ ◄───────────────────────────────────── │перегляд│
              └─────────┘           Esc / q / ←                  └────────┘
               │  ▲  │  ▲                                         │   ▲
            n,d,:  │ e │  Enter/Esc                              e │   │ Esc (без змін)
               ▼  │  │  │                                          ▼   │
          ┌────────┐ │  │                                        ┌────────┐
          │ PROMPT │─┘  └────────────── e ─────────────────────► │  EDIT  │
          │ рядок  │                                             │редагув.│
          └────────┘                                             └────────┘
                                                                  │     ▲
                                                Esc / ^Q зі змінами│     │ Esc (скасувати)
                                                                  ▼     │
                                                             ┌──────────┐
                                                             │ CONFIRM  │──► y: зберегти → VIEW / вихід
                                                             │ y/n/Esc  │──► n: відкинути → VIEW / вихід
                                                             └──────────┘
   ? з BROWSE або VIEW → HELP (переглядач довідки) → Esc повертає в той стан, звідки відкрили
   q / ^Q з BROWSE → вихід
```

**Виняткові стани** не входять у граф. Нечитабельний або бінарний файл, неіснуючий шлях,
відмова в доступі кидають виняток (`FileManagerError`, `OSError`). Застосунок перехоплює
його в одному місці (`FileManagerApp.handle_key`), показує червоним у рядку статусу,
і користувач лишається в тому самому стані.

## Архітектура

```
files.py                точка входу (composition root): LocalFileSystem + AnsiTerminal
fileman/
  app.py                FileManagerApp — контекст станів і головний цикл
  modes/
    base.py             Mode — базовий стан (+ Template Method для малювання)
    browser.py          BrowserMode — список файлів, навігація, командний рядок
    viewer.py           ViewerMode — перегляд файлу або довідки
    editor.py           EditorMode — редагування, збереження, підтвердження
    prompt.py           PromptMode / ConfirmMode — короткі діалоги
  buffer.py             TextBuffer — документ редактора (чиста логіка, Memento для undo)
  canvas.py             Canvas — віртуальний екран: заголовок / тіло / два рядки футера
  renderer.py           AnsiRenderer — Canvas → ANSI escape-послідовності
  terminal.py           ITerminal / AnsiTerminal — єдине місце, що чіпає справжню консоль
  keys.py               Key, KeyDecoder — байти термінала → клавіші
  filesystem.py         IFileSystem / LocalFileSystem / MemoryFileSystem
  viewport.py           Viewport — прокрутка, спільна для всіх режимів
  status.py             StatusBar — рядок статусу (реалізує IDisplayer)
  help.py               довідка, зібрана системою структурованого тексту
  errors.py             виняткові стани
```

Кожен клас має одну відповідальність. Режими не пишуть escape-коди: вони малюють на `Canvas`,
а в термінал його перетворює `AnsiRenderer`. Режими не звертаються до `os` чи `pathlib`:
вони отримують `IFileSystem`. Справжню консоль бачить лише `AnsiTerminal` (raw mode,
альтернативний екран, читання байтів, розмір вікна, сигнал зміни розміру `SIGWINCH`).

## Шаблони проєктування

| Шаблон | Де | Навіщо |
|---|---|---|
| **State** | `FileManagerApp` + `modes/` | Кожен режим — окремий клас. Та сама клавіша в різних режимах означає різне: Enter відкриває каталог у списку й розбиває рядок у редакторі. Переходи між станами — виклики `app.switch(...)`. |
| **Template Method** | `Mode.render()` | Порядок малювання фіксований (заголовок → тіло → футер); режими заповнюють лише тіло й підказки. |
| **Command** | мапи клавіш = словник `FunctionCommand` | Клавіша — селектор, дія — обробник. Нова прив'язка — один виклик `bind()`. |
| **Memento** | `TextBuffer` / `BufferMemento` | Undo в редакторі: знімок перед кожною зміною. Набір літер в одному рядку групується в один крок. |
| **Dependency Inversion / заміна моком** | `ITerminal`, `IFileSystem` | Увесь застосунок тестується без консолі й диска: `ScriptedTerminal` + `MemoryFileSystem`. |
| **Builder** | `help.py` | Довідка збирається через `DocumentBuilder` із системи тексту. |

## Перевикористаний код з попередніх практичних

- `cli/framework` — **`Command`/`FunctionCommand`** (з практичного 13; раніше `CommandRegistry`
  з практичного 4). Мапа клавіш кожного режиму — словник «клавіша → `FunctionCommand`», а описи
  команд автоматично наповнюють довідку.
- `cli/framework/args.py` — **`ArgsParser`** (раніше `parse_line`). Командний рядок `:` у списку файлів
  (`:cd src`, `:open README.md`, `:new notes.txt`, `:mkdir tmp`, `:q`) розбирається тим самим
  парсером, що й основний CLI, і виконується відповідною `Command`.
- `core/text` — **`DocumentBuilder`** (практичні 3 і 9). Довідка — справжній структурований
  документ із заголовками для кожного режиму, згенерований з мап клавіш, тож він не може
  розійтися з реальними прив'язками.
- `infra/displayer.py` — **`IDisplayer` / `Message`** (практична 5). Рядок статусу реалізує
  `IDisplayer`, тому все, що вже вміло звітувати через displayer, може писати в статус.
- Ідея **Memento** з гри (практична 11) — для undo в редакторі.

## Тести — `tests/test_fileman.py` (70 нових, разом 281)

Застосунок у тестах працює повністю: `ScriptedTerminal` подає клавіші й записує вивід,
`MemoryFileSystem` замінює диск, а перевірки йдуть по вмісту `Canvas`.
- **Декодер клавіш:** стрілки та їх альтернативні послідовності, PgUp/PgDn, Home/End, Delete,
  Ctrl-комбінації, Esc, кирилиця, змішані фрагменти, невідомі послідовності.
- **Canvas і рендерер:** регіони, обрізання за шириною, позиціонування рядків, кольори, курсор.
- **TextBuffer:** набір, перенос із збереженням відступу, склеювання рядків, рух курсора, undo
  з групуванням, ознака змін, кінцевий перенос рядка.
- **Файлові системи:** сортування, приховані файли, бінарні й завеликі файли (`LocalFileSystem`
  на справжній тимчасовій теці).
- **Стани й переходи:** навігація й повернення з виділенням попереднього каталогу, порожній
  каталог, прокрутка, діалоги (створити, скасувати), командний рядок і помилки в ньому,
  переглядач (межі прокрутки, позиція), редактор (збереження, підтвердження y/n/Esc, вихід
  зі змінами, undo, курсор, горизонтальна прокрутка), довідка (повернення в попередній стан).
- **Головний цикл і справжній `AnsiTerminal`:** читання клавіш через pipe, безпечний розмір
  за замовчуванням, відмова запускатися без інтерактивного термінала.

Окремо застосунок перевірено вручну в справжньому псевдотерміналі: перегляд, редагування
з підтвердженням збереження, створення файлу, командний рядок, бінарний файл, довідка.
Результат цієї перевірки — знімки в `docs/screenshots/`.
